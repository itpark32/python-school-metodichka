# `dataclass`

<p class="reading-time">Чтение: 10–12 минут · Практика: 20–30 минут</p>
<div class="tags"><span class="tag tag--plus">Python+</span></div>

`dataclass` сокращает служебный код класса, основная роль которого — хранить данные.

!!! abstract "Фокус"
    - **Нужно знать:** декоратор `@dataclass` и аннотации полей.

```python
from dataclasses import dataclass

@dataclass
class Student:
    name: str
    score: int

masha = Student("Маша", 78)
masha.score = 85
print(masha)
```

Python создаёт `__init__` и удобное текстовое представление. `str` и `int` — аннотации ожидаемых типов, но сами по себе не проверяют ввод во время выполнения.

## Что сокращает декоратор

Обычному классу-хранилищу пришлось бы вручную написать конструктор и присвоить поля. `@dataclass` создаёт этот служебный код по аннотациям; объекты также удобно сравниваются по значениям.

```python
@dataclass
class Book:
    title: str
    pages: int
    read: bool = False
```

Теперь `Book("Капитанская дочка", 160)` создаёт непрочитанную книгу. Поля со значениями по умолчанию записывают после обязательных. Аргументы можно передавать по именам.

`dataclass` хорош для прозрачной структуры данных. Если создание требует сложной проверки или поведение важнее полей, обычный класс может быть яснее. Аннотация помогает читателю и инструментам, но неверный тип автоматически не запрещает.

## Разбор задач

Начнём с прямого применения темы, затем объединим знакомые приёмы и разберём более сложную задачу.

Если данные заданы прямо в коде, для дополнительных тестов заменяйте начальные значения на данные из таблицы.

### Задача 1. Карточка книги без конструктора

#### Условие

Опишите dataclass Book с полями title: str, pages: int и read: bool = False. Создайте книгу "Python" на 150 страниц и выведите поля через пробел.

#### Как рассуждать

Объект в основном хранит данные, поэтому ручной __init__ не нужен. Обязательные поля идут первыми, а поле со значением по умолчанию — последним. При создании без read книга будет непрочитанной.

#### Алгоритм

1. Импортируйте dataclass.
2. Опишите поля и значение по умолчанию.
3. Создайте книгу и выведите поля.

#### Решение

```python
from dataclasses import dataclass

@dataclass
class Book:
    title: str
    pages: int
    read: bool = False

book = Book("Python", 150)
print(book.title, book.pages, book.read)
```

#### Разбор решения

Декоратор создаёт конструктор по аннотациям. Аннотации сами по себе не проверяют типы при запуске — данные должны соответствовать договору задачи. Вывод полей отдельно позволяет явно увидеть значение False по умолчанию.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| Book("Python", 150) | обычный случай | Python 150 False |
| read=True | переопределение значения по умолчанию | Python 150 True |

**Ответ:** для первого теста — Python 150 False.

### Задача 2. Равенство по данным

#### Условие

Опишите dataclass Point с целыми x и y. Создайте first = Point(2, 3) и second = Point(2, 3). Выведите результат сравнения, увеличьте x у second на 1, затем снова сравните и выведите x у first.

#### Как рассуждать

Это два отдельных объекта с одинаковыми полями, поэтому dataclass сравнит их по значениям и сначала даст True. После изменения одного поля данные различаются. Первый объект при этом не должен измениться.

#### Алгоритм

1. Создайте два экземпляра.
2. Сравните их через ==.
3. Измените только second.x.
4. Снова сравните и проверьте first.x.

#### Решение

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

first = Point(2, 3)
second = Point(2, 3)
print(first == second)
second.x += 1
print(first == second)
print(first.x)
```

#### Разбор решения

Сравнение по полям создаётся автоматически. Равенство значений не означает, что имена ссылаются на один объект: мы дважды вызываем конструктор. Если написать `second = first`, изменение затронуло бы одну общую точку.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| одинаковые исходные точки | обычный случай | True<br>False<br>2 |
| second изначально Point(1,3) | изменение делает точки равными | False<br>True<br>2 |

**Ответ:** для первого теста — True; False; 2.

### Задача 3. Заявки с приоритетом

#### Условие

Опишите dataclass Application с полями name, score и approved=False. Для списка заявок Анна 80, Борис 95, Вера 80 установите approved=True у баллов не ниже 80. Выведите одобренные заявки по убыванию балла, при равенстве по имени. Каждая строка — имя и балл.

#### Как рассуждать

Здесь вместе работают структура данных, изменение поля, фильтр и сортировка по ключу. Поле approved хранит решение для каждой заявки; отдельный список содержит ссылки только на одобренные объекты. Критерий сортировки не следует путать с порогом допуска.

#### Алгоритм

1. Опишите dataclass.
2. Для каждой заявки вычислите approved и отберите успешные.
3. Отсортируйте по ключу (-score, name).
4. Выведите имена и баллы.

#### Решение

```python
from dataclasses import dataclass

@dataclass
class Application:
    name: str
    score: int
    approved: bool = False

def priority(application):
    return -application.score, application.name

applications = [Application("Анна", 80), Application("Борис", 95), Application("Вера", 80)]
selected = []
for application in applications:
    application.approved = application.score >= 80
    if application.approved:
        selected.append(application)
for application in sorted(selected, key=priority):
    print(application.name, application.score)
```

#### Разбор решения

Знак минус у балла даёт убывание, а имя остаётся по возрастанию. Изменение approved не влияет на score. Пустой результат корректен: цикл вывода не выполнится. Пример учебный и не требует экзаменационной привязки.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| Анна 80, Борис 95, Вера 80 | граница и равенство баллов | Борис 95<br>Анна 80<br>Вера 80 |
| одна заявка с 79 | ниже порога | нет строк вывода |
| пустой список | нет заявок | нет строк вывода |

**Ответ:** для первого теста — Борис 95; Анна 80; Вера 80.
