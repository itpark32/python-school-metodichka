# Как оценивать эффективность

<p class="reading-time">Чтение: 12–15 минут · Практика: 20–30 минут</p>
<div class="tags"><span class="tag">10–11 класс</span><span class="tag tag--ege">ЕГЭ</span><span class="tag tag--plus">Углублённый уровень</span></div>

Сложность показывает, как растёт число действий при росте данных, а не точное время в секундах.

!!! abstract "Фокус"
    - **Нужно знать:** `O(1)`, `O(n)`, `O(n²)`, `O(log n)` на интуитивном уровне.

| Алгоритм | Рост | Для 1 000 000 элементов |
|---|---:|---:|
| доступ по индексу | `O(1)` | одно действие |
| линейный поиск | `O(n)` | до миллиона |
| бинарный поиск | `O(log n)` | около 20 |
| двойной полный проход | `O(n²)` | около триллиона |

Константы важны в реальной работе, но сначала сравнивают характер роста. Два последовательных прохода — `O(n)`, а вложенный полный цикл — обычно `O(n²)`. Предварительная сортировка может окупиться, если потом выполняется много быстрых поисков.

## Как читать код

Один цикл по `n` элементам даёт линейный рост. Два последовательных цикла дают `n + n = 2n`, то есть тот же характер `O(n)`. Вложенные полные циклы дают `n · n`. Цикл, который каждый раз делит число или диапазон пополам, выполняется порядка `log n` раз.

Не всякая вложенность означает `n²`: если внутренний указатель за всю программу только движется вперёд и не сбрасывается, общее число шагов может остаться линейным. Считайте фактические движения, а не только отступы.

## Время и память

Алгоритм оценивают и по дополнительной памяти. Потоковая сумма использует `O(1)` памяти, список всех `n` чисел — `O(n)`. Иногда память обменивают на скорость: множество уже встреченных значений ускоряет проверку повторов, но занимает место.

Оценка нужна до реализации: при `n = 100 000` квадратный алгоритм почти наверняка неприемлем, а несколько линейных проходов обычно разумны.

### Задача 1. Два прохода вместо вложенности

#### Условие

Введите n от 0 до 1000. Выполните два последовательных цикла по range(n), в каждом увеличивая общий счётчик. Выведите число действий и оцените рост.

#### Как рассуждать

Каждый цикл делает n увеличений, вместе они дают 2n. Циклы идут один после другого, поэтому длины складываются, а не перемножаются. При удвоении n число действий тоже удваивается.

#### Алгоритм

1. Обнулите счётчик.
2. Выполните первый проход.
3. Выполните второй проход.
4. Выведите счётчик.

#### Решение

```python
n = int(input())
actions = 0
for _ in range(n):
    actions += 1
for _ in range(n):
    actions += 1
print(actions)
```

#### Разбор решения

Речь о числе увеличений счётчика, а не обо всех машинных инструкциях и не о секундах. Коэффициент 2 не меняет линейный характер роста: время O(n), дополнительная память O(1).

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| 3 | обычный случай | 6 |
| 6 | удвоение входа | 12 |
| 0 | пустые диапазоны | 0 |

**Ответ:** для первого теста — 6.

### Задача 2. Пары без зеркальных повторов

#### Условие

Введите n от 0 до 1000. Посчитайте число пар индексов i < j, не сохраняя сами пары. Объясните сложность.

#### Как рассуждать

Внутренний цикл сужается: для первого индекса есть n - 1 партнёр, для следующего n - 2. Сумма равна n*(n - 1)//2. Несмотря на сокращение вдвое по сравнению с полным квадратом, главный рост остаётся квадратичным.

#### Алгоритм

1. Переберите первый индекс.
2. Второй начинайте с i + 1.
3. Посчитайте пары и выведите количество.

#### Решение

```python
n = int(input())
count = 0
for i in range(n):
    for j in range(i + 1, n):
        count += 1
print(count)
```

#### Разбор решения

Условие i < j исключает пару с собой и зеркальную пару. Для n = 4 получается 3 + 2 + 1 = 6. Время O(n²), но дополнительная память O(1): пары нигде не накапливаются.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| 4 | обычный случай | 6 |
| 1 | себя не выбираем | 0 |
| 0 | нет индексов | 0 |
| 8 | рост быстрее линейного | 28 |

**Ответ:** для первого теста — 6.

### Задача 3. Один указатель на весь проход

#### Условие

В отсортированном списке положительных чисел `numbers = [1, 2, 4, 7]` посчитайте пары индексов i < j, для которых сумма ≤ limit = 8. Используйте два указателя, без полного двойного перебора.

#### Как рассуждать

Если самая маленькая и самая большая из оставшихся дают допустимую сумму, то с этой маленькой подходят все партнёры между ними. Добавим сразу right - left пар и сдвинем left. Если сумма велика, самое большое число не подходит ни с одним оставшимся — уменьшим right.

#### Алгоритм

1. Поставьте указатели на края.
2. При допустимой сумме добавьте right - left и сдвиньте left.
3. Иначе сдвиньте right влево.
4. Выведите количество.

#### Решение

```python
numbers = [1, 2, 4, 7]
limit = 8
left = 0
right = len(numbers) - 1
count = 0
while left < right:
    if numbers[left] + numbers[right] <= limit:
        count += right - left
        left += 1
    else:
        right -= 1
print(count)
```

#### Разбор решения

Для примера подходят (1,2), (1,4), (1,7), (2,4): четыре пары. Каждый шаг уменьшает расстояние между указателями на 1, поэтому после готовой сортировки время O(n), память O(1). Если вход не отсортирован, сначала нужна сортировка со своей стоимостью.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| [1,2,4,7], limit 8 | обычный случай | 4 |
| limit 2 | нет допустимых пар | 0 |
| [1,1,1], limit 8 | равные значения на разных позициях | 3 |
| [], limit 8 | пустые данные | 0 |

**Ответ:** для первого теста — 4.
