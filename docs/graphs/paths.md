Обход графа отвечает, какие вершины достижимы. Разные задачи требуют разного состояния: посещённые вершины, очередь, число путей или текущие расстояния.

!!! abstract "Фокус"
    - **Нужно знать:** идеи DFS, BFS и Дейкстры.
    - **Нужно уметь:** найти достижимость с DFS.

## Поиск в глубину

```python
def dfs(vertex, graph, visited):
    visited.add(vertex)
    for neighbour in graph[vertex]:
        if neighbour not in visited:
            dfs(neighbour, graph, visited)

visited = set()
dfs(1, graph, visited)
print(4 in visited)
```

`visited` защищает от повторов и циклов. BFS использует очередь и слоями находит кратчайшее число рёбер в невзвешенном графе.

Вершину отмечают сразу при входе, до переходов к соседям. Иначе цикл в графе успеет вернуть обход к той же вершине. DFS и BFS отвечают на достижимость одинаково, но идут в разном порядке. Для восстановления маршрута хранят для каждой новой вершины её предка.

## Количество путей в DAG

```python
def count_paths(vertex, finish, graph):
    if vertex == finish:
        return 1
    total = 0
    for neighbour in graph[vertex]:
        total += count_paths(neighbour, finish, graph)
    return total
```

Для большого графа результаты вершин запоминают, чтобы не считать повторно. Это безопасно в DAG; цикл потребует другой логики. Базовый случай финиша равен 1: найден один завершённый путь. Если финиш недостижим, сумма естественно останется нулём.

## Идея Дейкстры

```python
import heapq

def dijkstra(graph, start):
    distance = {start: 0}
    queue = [(0, start)]
    while queue:
        current, vertex = heapq.heappop(queue)
        if current != distance[vertex]:
            continue
        for neighbour, weight in graph[vertex]:
            new = current + weight
            if neighbour not in distance or new < distance[neighbour]:
                distance[neighbour] = new
                heapq.heappush(queue, (new, neighbour))
    return distance
```

Очередь с приоритетом первой отдаёт вершину с наименьшей известной длиной. Алгоритм требует неотрицательных весов. Словарь `distance` хранит лучшие найденные расстояния. Новая длина записывается только при улучшении. Запись очереди может устареть после более удачного пути, поэтому проверяется `current != distance[vertex]`.

## Выбор алгоритма

| задача | подход |
|---|---|
| достижимость | DFS или BFS |
| минимум рёбер | BFS |
| количество путей в DAG | динамика или рекурсия с запоминанием |
| кратчайший вес при неотрицательных рёбрах | Дейкстра |

## Разбор задач

Начнём с прямого применения темы, затем объединим знакомые приёмы и разберём более сложную задачу.

### Задача 1. Достижимость с циклом

#### Условие

Дан граф `graph = {1: [2], 2: [1, 3], 3: [], 4: []}`. Через DFS определите, достижима ли введённая вершина target из 1. Выведите True или False. Цель — один из ключей графа.

#### Как рассуждать

В графе есть цикл 1 → 2 → 1. Чтобы обход не возвращался бесконечно, отмечаем вершину до перехода к соседям. Изолированная вершина 4 останется вне посещённых.

#### Алгоритм

1. Создайте множество visited.
2. При входе в вершину отметьте её.
3. Рекурсивно обойдите только ещё не посещённых соседей.
4. Проверьте принадлежность цели множеству.

#### Решение

```python
graph = {1: [2], 2: [1, 3], 3: [], 4: []}
def dfs(vertex, graph, visited):
    visited.add(vertex)
    for neighbour in graph[vertex]:
        if neighbour not in visited:
            dfs(neighbour, graph, visited)

visited = set()
dfs(1, graph, visited)
target = int(input())
print(target in visited)
```

#### Разбор решения

Функция получает граф и множество параметрами и добавляет значения в переданное visited. Проверка до нового вызова разрывает цикл, но не мешает найти вершину 3. Начало достижимо из себя путём из нуля рёбер. Для больших глубоких графов понадобится обход без глубокой рекурсии.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| target = 3 | обычный случай | True |
| target = 4 | недостижимая вершина | False |
| target = 1 | совпадение со стартом | True |

**Ответ:** для первого теста — True.

### Задача 2. Сколько маршрутов в DAG

#### Условие

Дан ориентированный граф без циклов `graph = {1: [2, 3], 2: [3, 4], 3: [4], 4: [], 5: []}`. Найдите число путей из 1 во введённую вершину finish. Все рёбра записаны по одному разу.

#### Как рассуждать

Каждый путь из вершины начинается с одного исходящего ребра. Поэтому число путей равно сумме ответов соседей. На финише возвращаем 1 — один уже завершённый путь. В тупике вне финиша сумма равна нулю.

#### Алгоритм

1. Если текущая вершина — финиш, верните 1.
2. Иначе сложите ответы всех соседей.
3. Запустите рекурсию от 1 и выведите число путей.

#### Решение

```python
graph = {1: [2, 3], 2: [3, 4], 3: [4], 4: [], 5: []}
def count_paths(vertex, finish):
    if vertex == finish:
        return 1
    total = 0
    for neighbour in graph[vertex]:
        total += count_paths(neighbour, finish)
    return total

finish = int(input())
print(count_paths(1, finish))
```

#### Разбор решения

До 4 есть пути 1–2–4, 1–3–4 и 1–2–3–4: ответ 3. Отдельный visited здесь не используем: он мог бы запретить разные пути через одну вершину. Отсутствие циклов — обязательное условие завершения; для больших DAG результаты следует запоминать.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| finish = 4 | обычный случай | 3 |
| finish = 5 | изолированный финиш | 0 |
| finish = 1 | пустой путь до себя | 1 |
| finish = 3 | прямой и непрямой путь | 2 |

**Ответ:** для первого теста — 3.

### Задача 3. Кратчайшая стоимость

#### Условие

Дан ориентированный граф с неотрицательными весами: `graph = {1: [(2, 4), (3, 1)], 2: [(4, 2)], 3: [(2, 1), (4, 8)], 4: [], 5: []}`. Найдите Дейкстрой кратчайший вес из 1 во введённую цель. При отсутствии пути выведите `нет пути`.

#### Как рассуждать

Обход с простым признаком посещения не хранит стоимость. Нужны лучшие расстояния и очередь кандидатов, из которой первой извлекается наименьшая стоимость. Если расстояние улучшилось, старую запись очереди позже пропускаем.

#### Алгоритм

1. Задайте расстояние до старта 0 и поместите его в очередь.
2. Извлекайте ближайшего кандидата.
3. Улучшайте расстояния соседей и добавляйте новые записи.
4. Выведите расстояние цели или сообщение.

#### Решение

```python
import heapq

graph = {1: [(2, 4), (3, 1)], 2: [(4, 2)], 3: [(2, 1), (4, 8)], 4: [], 5: []}
distance = {1: 0}
queue = [(0, 1)]
while queue:
    current, vertex = heapq.heappop(queue)
    if current != distance[vertex]:
        continue
    for neighbour, weight in graph[vertex]:
        new_distance = current + weight
        if neighbour not in distance or new_distance < distance[neighbour]:
            distance[neighbour] = new_distance
            heapq.heappush(queue, (new_distance, neighbour))
target = int(input())
if target in distance:
    print(distance[target])
else:
    print("нет пути")
```

#### Разбор решения

Используется уже показанный в теории heapq: heappop берёт минимальную пару, heappush добавляет кандидата. До 4 выгоднее идти 1–3–2–4 с весом 4, а не по первому найденному маршруту. Пропуск устаревших записей нужен после улучшения пути до 2 с 4 до 2.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| target = 4 | лучший путь найден после улучшения | 4 |
| target = 2 | непрямой путь дешевле прямого | 2 |
| target = 5 | недостижимая цель | нет пути |
| target = 1 | старт | 0 |

**Ответ:** для первого теста — 4.
