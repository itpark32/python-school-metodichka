# Линейный и бинарный поиск

<p class="reading-time">Чтение: 12–15 минут · Практика: 25–35 минут</p>
<div class="tags"><span class="tag">9–11 класс</span><span class="tag tag--ege">ЕГЭ</span><span class="tag tag--plus">Углублённый уровень</span></div>

Линейный поиск проверяет все элементы. Бинарный сравнивает с серединой и каждый раз отбрасывает половину — но требует сортировки.

!!! abstract "Фокус"
    - **Нужно знать:** границы `left`, `right`, середина.
    - **Нужно уметь:** объяснить, почему поиск завершается.

```python
left = 0
right = len(numbers) - 1
target = 42
position = -1

while left <= right:
    middle = (left + right) // 2
    if numbers[middle] == target:
        position = middle
        break
    if numbers[middle] < target:
        left = middle + 1
    else:
        right = middle - 1
```

При неравенстве середину уже проверили, поэтому новая граница сдвигается на один. Для миллиона элементов бинарному поиску нужно около 20 сравнений, линейному — до миллиона.

## Инвариант границ

Перед каждым шагом искомое значение, если оно существует, находится внутри отрезка `left..right`. Если середина меньше цели, вся левая часть вместе с серединой уже не подходит. Поэтому пишут `left = middle + 1`. Без `+1` границы могут перестать сужаться.

| шаг | left | right | middle | значение | действие |
|---:|---:|---:|---:|---:|---|
| 1 | 0 | 5 | 2 | 7 | искать справа |
| 2 | 3 | 5 | 4 | 15 | искать слева |
| 3 | 3 | 3 | 3 | 11 | найдено |

Таблица относится к списку `[2, 4, 7, 11, 15, 20]` и цели 11.

## Когда какой поиск

Один поиск в небольшом несортированном наборе проще выполнить линейно. Сортировать только ради одного запроса часто дороже. Бинарный поиск выгоден, когда данные уже упорядочены или запросов много. Если есть повторы и нужен первый или последний индекс, обычный выход при равенстве недостаточен — границу продолжают сдвигать.

!!! info "Python+"
    Модуль `bisect` выполняет бинарный поиск позиции вставки, но сначала важно понять границы вручную.

## Разбор задач

Начнём с прямого применения темы, затем объединим знакомые приёмы и разберём более сложную задачу.

Если данные заданы прямо в коде, для дополнительных тестов заменяйте начальные значения на данные из таблицы.

### Задача 1. Поиск цели в отсортированном списке

#### Условие

В отсортированном списке `numbers = [2, 5, 9, 14, 20]` найдите введённое целое target бинарным поиском. Выведите его индекс или -1. Все элементы различны.

#### Как рассуждать

Границы описывают ещё не исключённую часть списка. Сравнение с серединой позволяет отбросить половину, потому что список упорядочен. Если середина проверена и не подходит, её больше не включаем в диапазон.

#### Алгоритм

1. Задайте границы от 0 до len - 1.
2. Сравнивайте цель со средней позицией.
3. При неравенстве сдвигайте границу за середину.
4. Выведите найденный индекс или -1.

#### Решение

```python
numbers = [2, 5, 9, 14, 20]
target = int(input())
left = 0
right = len(numbers) - 1
position = -1
while left <= right:
    middle = (left + right) // 2
    if numbers[middle] == target:
        position = middle
        break
    if numbers[middle] < target:
        left = middle + 1
    else:
        right = middle - 1
print(position)
```

#### Разбор решения

`left <= right` сохраняет проверку последнего кандидата. Сдвиг на 1 нужен для завершения. Для цели 14 проверяются 9, затем 14; для пустого списка right = -1 и поиск сразу завершается.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| цель 14 | обычный случай | 3 |
| цель 2 | первый элемент | 0 |
| цель 21 | больше последнего | -1 |
| []; цель 2 | пустые границы | -1 |

**Ответ:** для первого теста — 3.

### Задача 2. Первое из одинаковых

#### Условие

В неубывающем списке `numbers = [1, 3, 3, 3, 8]` найдите индекс первого вхождения введённой цели или -1.

#### Как рассуждать

При равенстве середины ещё нельзя останавливаться: такое же значение может быть левее. Запомним текущую находку, но продолжим поиск в левой части. Если позже найдём более раннюю позицию, заменим ответ.

#### Алгоритм

1. Инициализируйте бинарный поиск.
2. При значении не меньше цели двигайте правую границу влево.
3. При равенстве дополнительно сохраняйте индекс.
4. Выведите последний сохранённый ответ.

#### Решение

```python
numbers = [1, 3, 3, 3, 8]
target = int(input())
left = 0
right = len(numbers) - 1
position = -1
while left <= right:
    middle = (left + right) // 2
    if numbers[middle] >= target:
        if numbers[middle] == target:
            position = middle
        right = middle - 1
    else:
        left = middle + 1
print(position)
```

#### Разбор решения

Здесь нет break при равенстве. Уже найденная позиция сохраняется, даже если следующий просмотр слева не обнаружит цель. Обычный бинарный поиск мог бы вернуть середину группы повторов, что не отвечает условию.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| цель 3 | обычный случай | 1 |
| цель 8 | последний элемент | 4 |
| цель 2 | между существующими значениями | -1 |

**Ответ:** для первого теста — 1.

### Задача 3. Сколько значений не больше порога

#### Условие

Для неубывающего списка `numbers = [2, 4, 4, 7, 9]` найдите количество элементов ≤ введённого порога limit. Используйте бинарный поиск границы.

#### Как рассуждать

Ищем первую позицию, где значение уже больше порога. Все позиции перед ней подходят; их количество равно индексу этой границы. Удобно держать полуоткрытый диапазон [left, right), где right может быть равен длине.

#### Алгоритм

1. Задайте left = 0 и right = len.
2. Пока границы различны, проверяйте середину.
3. При значении ≤ limit двигайте left за середину, иначе right к середине.
4. Выведите left.

#### Решение

```python
numbers = [2, 4, 4, 7, 9]
limit = int(input())
left = 0
right = len(numbers)
while left < right:
    middle = (left + right) // 2
    if numbers[middle] <= limit:
        left = middle + 1
    else:
        right = middle
print(left)
```

#### Разбор решения

В этом варианте right не включается, поэтому присваивание `right = middle` не зацикливает поиск. Если подходят все элементы, ответ равен длине; если ни один — нулю. Саму позицию len никогда не читаем: middle при left < right всегда меньше right.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| limit = 4 | повторы на границе | 3 |
| limit = 1 | не подходит никто | 0 |
| limit = 9 | подходят все | 5 |
| []; limit = 4 | пустой список | 0 |

**Ответ:** для первого теста — 3.
