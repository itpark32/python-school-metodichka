# Ошибки и отладка

<p class="reading-time">Чтение: 12–15 минут · Практика: 20–30 минут</p>
<div class="tags"><span class="tag">8 класс</span><span class="tag">9 класс</span><span class="tag tag--plus">Python+</span></div>

Ошибка — не поражение, а информация о том, где ожидания расходятся с работой программы.

Отладка — это короткое расследование. Есть ожидаемое поведение, фактическое поведение и первый шаг, на котором они расходятся. Задача программиста — найти этот шаг, а не менять код наугад.

!!! abstract "Фокус"
    - **Нужно знать:** синтаксические, исполнительные и логические ошибки.
    - **Нужно уметь:** прочитать последнюю строку traceback и найти строку кода.
    - **Полезно знать:** маленький проверочный пример быстрее случайных правок.

## 1. Три группы

1. **Синтаксическая:** забыты `:`, скобка или отступ — Python не может прочитать код.
2. **Ошибка выполнения:** код запустился, но встретил `ValueError`, `IndexError`, деление на ноль или отсутствующий файл.
3. **Логическая:** программа работает без сообщения, но ответ неверен.

```python
number = int(input())  # ValueError, если ввести "три"
print(10 / number)     # ZeroDivisionError, если ввести 0
```

Сообщение Python читают снизу вверх. В последней строке находятся тип ошибки и объяснение, чуть выше — строка вашей программы.

| ошибка | частая причина | что проверить |
|---|---|---|
| `NameError` | имя ещё не создано или опечатка | написание переменной |
| `TypeError` | операция не подходит типам | результат `input`, типы операндов |
| `IndexError` | индекс вышел за список | границы цикла и длину списка |
| `ZeroDivisionError` | делитель стал нулём | условие до деления |
| `FileNotFoundError` | неверный путь | имя и рабочую папку |

## 2. Алгоритм отладки

1. Прочитайте последнюю строку сообщения.
2. Найдите указанный файл и номер строки.
3. Проверьте значения перед этой строкой.
4. Временно добавьте `print(variable)`.
5. Запустите простой тест, ответ которого знаете заранее.

Для цикла полезно печатать номер шага и накопители: `print(i, number, count)`.

## 3. Как искать логическую ошибку

Если программа не падает, но отвечает неверно, уменьшите пример. Вместо ста чисел возьмите три и посчитайте ответ вручную. Затем составьте трассировочную таблицу.

```python
numbers = [2, 5, 8]
total = 0

for number in numbers:
    if number % 2 == 0:
        total = number  # должно быть total += number
```

После первого шага `total == 2`, после второго остаётся 2, после третьего становится 8. Ожидаемая сумма 10 показывает место расхождения. Хороший набор тестов включает обычный случай, минимальный размер, границу условия, отсутствие подходящих элементов и отрицательные числа, если они разрешены.

## 4. Частые ошибки

- исправлять строку наугад, не читая тип ошибки;
- смотреть только на последнюю строку кода, хотя неверное значение появилось раньше;
- тестировать только на одном «удобном» наборе;
- оставлять отладочный вывод в экзаменационном ответе.

## 5. Разбор задач

Начнём с прямого применения темы, затем объединим знакомые приёмы и разберём более сложную задачу.

### Задача 1. Потерянное преобразование

#### Условие

Программа читает цену: `price = input()`, затем выполняет `print(price * 3)`. Исправьте её, чтобы для целой неотрицательной цены выводилась стоимость трёх товаров.

#### Как рассуждать

Если ввести 12, исходный код выведет 121212: это повторение текста, а не умножение числа. Ошибка логическая, программа не падает. Нужно изменить тип данных до вычисления.

#### Алгоритм

1. Сравните ожидаемые 36 и фактические 121212.
2. Преобразуйте ввод через int.
3. Повторите проверку на нуле и обычной цене.

#### Решение

```python
price = int(input())
print(price * 3)
```

#### Разбор решения

`int` устраняет причину ошибки в месте ввода. Добавлять его только к уже повторённому тексту поздно: `int("121212")` останется неверной стоимостью. Нулевой тест отличает число 0 от строки из трёх нулей.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| 12 | обычный случай | 36 |
| 0 | нулевая цена | 0 |
| 1 | минимальная положительная цена | 3 |

**Ответ:** для первого теста — 36.

### Задача 2. Ошибка на границе зачёта

#### Условие

Зачёт начинается с 60 баллов. В неверном решении стоит `if score > 60`. Напишите исправленную программу: от 60 выводится `зачёт`, иначе `незачёт`.

#### Как рассуждать

Для большинства значений ошибка незаметна: и 59, и 61 обрабатываются ожидаемо. Минимальный контрпример — ровно 60. На нём строгое сравнение исключает разрешённую границу.

#### Алгоритм

1. Прочитайте балл.
2. Замените строгое сравнение на включающее границу.
3. Выведите ровно один результат.

#### Решение

```python
score = int(input())
if score >= 60:
    print("зачёт")
else:
    print("незачёт")
```

#### Разбор решения

`>=` исправляет потерянное равенство. `else` связан с этим же `if`, поэтому результат один. Если второй `print` оставить без отступа и без `else`, программа станет сообщать незачёт даже при успехе.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| 60 | контрпример для старого кода | зачёт |
| 59 | перед границей | незачёт |
| 61 | после границы | зачёт |

**Ответ:** для первого теста — зачёт.

### Задача 3. Зависимость от порядка команд

#### Условие

Даны команды `a = a + b`, затем `b = a - 2 * b`. Начальные a и b вводятся с разных строк. Ученик считает, что обе правые части используют исходные значения. Покажите исправленный ход рассуждения и выведите конечную пару.

#### Как рассуждать

Команды выполняются последовательно: второе выражение читает новое a и прежнее b. Для 5 и 2 после первой строки будет a = 7; затем b = 7 - 4 = 3. Ошибка находится в ручном прогнозе, а не в синтаксисе программы.

#### Алгоритм

1. Запишите начальные значения.
2. Выполните первую команду и обновите a.
3. Выполните вторую с новым a и выведите пару.

#### Решение

```python
a = int(input())
b = int(input())
a = a + b
b = a - 2 * b
print(a, b)
```

#### Разбор решения

Промежуточную пару нельзя пропускать. Для входа 5 и 2 трасса: `(5, 2) → (7, 2) → (7, 3)`. Если подставить старое a во вторую строку, получится 1 вместо 3. Такой пошаговый разбор нужен в школьных заданиях на выполнение алгоритма.

#### Проверка

| Данные | Почему проверяем | Результат |
|---|---|---|
| 5; 2 | обычный случай | 7 3 |
| 0; 0 | проверка нулей | 0 0 |
| -3; 4 | разные знаки | 1 -7 |

**Ответ:** для первого теста — 7 3.
